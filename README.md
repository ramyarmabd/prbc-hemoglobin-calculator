# PRBC hemoglobin response calculator

**Educational estimator—not clinically validated.**

Browser-only, mobile-friendly arithmetic for a theoretical hemoglobin rise and final hemoglobin after an entered PRBC amount. It does not recommend whether to transfuse, a dose, target Hb, or infusion rate.

Live site: https://ramyarmabd.github.io/prbc-hemoglobin-calculator/

## Run and test

No build, npm dependencies, or third-party assets are required. Serve this directory over HTTP (ES modules cannot reliably run from a file URL).

```sh
npm start    # Python 3 static server on http://127.0.0.1:4173
npm test     # Node.js >=22; tests import the actual production calculator.js
```

GitHub Pages serves `main` from the repository root. `.nojekyll` preserves the static files. The GitHub Actions calculation test workflow runs on pushes and pull requests. Pages' own deployment workflow is generated by GitHub after Pages is enabled.

## Methodology

1. Patient blood volume (mL) = weight (kg) × estimated blood volume (mL/kg), or the selected alternative blood-volume estimate.
2. Delivered Hb (g) = transfused PRBC volume (mL) × reference-bag Hb mass (g) ÷ reference-bag volume (mL).
3. Hb rise (g/dL) = delivered Hb (g) ÷ [blood volume (mL) ÷ 100].
4. Estimated final Hb = starting Hb + theoretical rise.

Assumptions: transfused red cells are retained and circulating blood volume is unchanged after equilibration. This is not an immediate post-infusion mixture/volume-expansion model. It does not predict fluid redistribution, sampling time, individual variability, red-cell loss, or survival.

Default mL/kg assumptions are adult 70, older infant/child 70, term newborn 80, and very preterm newborn 100; all are editable. NBA Appendix G gives approximately 70 for older infants/children, 80–85 for term infants and 100–120 for extremely preterm infants. Defaults do not establish applicability for a particular patient or gestational age.

Adult alternatives:

- Nadler: BV in mL = 1000 × (a × height in metres³ + b × kg + c). Historical male coefficients: 0.3669, 0.03219, 0.6041. Historical female coefficients: 0.3561, 0.03308, 0.1833. These population coefficients may not fit an individual's physiology.
- Lemmens–Bernstein–Brodsky: BV in mL = kg × 70 ÷ √(BMI/22), BMI = kg/metres². The index coefficient and reference BMI are adjustable. Any changes are explicitly labeled user-modified assumptions, not the published equation.
- Independently entered circulating volume in mL; available for all age groups.

Weight: kg or lb (1 lb = 0.45359237 kg). Height: cm or inches (1 inch = 2.54 cm). Adults: blood-bank units, actual mL, mL/kg, US liquid pints, Imperial pints. Pediatric groups: actual mL or mL/kg only. A blood-bank unit is not a literal pint: units use the reference-bag volume. 1 US liquid pint = 473.176473 mL; 1 Imperial pint = 568.26125 mL.

The reference examples are Canadian Blood Services 287 mL/55 g Hb and Lifeblood 258 mL/49 g Hb, verified on the supplier pages. They are product examples, not universal specifications. Aliquots use the reference concentration. Multiple-bag arithmetic assumes the same concentration for the entire entered volume.

## Separate RCH approximation

For children under 20 kg beyond the newborn period, the RCH volume formula can be algebraically inverted to rise (g/dL) = entered mL ÷ (5 × kg). The site presents this separately; it never changes the main estimate. Because RCH's accompanying guidance limits its increment scope to 20 g/L, the separate number is withheld if the entered amount implies a greater increment. This is an applicability restriction on that approximation, not a dose recommendation or a main-model clinical threshold.

## Adult research interpretation

[Roubinian et al., 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC6764268/) analyzed adult single-unit transfusion episodes using GEE regression. Multiple-unit episodes were excluded. The paper does not validate this mass-balance model, pediatric use, or multiple-unit predictions. The observed association between starting Hb and increment is not modeled here: starting Hb changes only the final sum. No optional research regression is implemented; there are no invented coefficients, intercept, correction factors or patient-specific uncertainty intervals. Regression effects must not simply be added to mass-balance arithmetic because overlapping effects could be counted twice.

## Exclusions and input handling

All numerical results are withheld for active bleeding, hemolysis, major fluid shifts/unstable blood volume, pregnancy, exchange transfusion, or another situation outside the assumptions. Applicability must be explicitly confirmed. Exclusion checks precede arithmetic in the production module.

Broad software limits are documented in the interface and `LIMITS` in `calculator.js`. They protect finite arithmetic; they are not clinical thresholds or validated patient-selection ranges. Zero amount is valid. Blank, malformed, negative, nonfinite, out-of-range, and incompatible inputs return no numbers. Editing any input immediately removes all previous numerical results. Switching age group clears the amount to avoid silently reinterpreting its unit.

## Privacy and accessibility

No identifiers, analytics, input submission, external calculation service, cookies, localStorage, sessionStorage, or other persistent patient-data storage. Values are used only in browser memory. GitHub Pages receives normal requests for static assets; the app never sends calculator inputs. Browser/OS history and autofill behavior remain outside application control. Reload or reset clears the application inputs. Source links open external websites only when followed.

Semantic headings, associated labels, keyboard focus outlines, skip link, live result/error status, readable contrast, minimum 48 px input controls, 16 px input text, responsive layout and no animations. Real-device and assistive-technology testing are distinct from desktop browser viewport testing.

## Validation status

Software verification only, with no clinical validation. The 100 automated tests import the exact production module, compare independent adult arithmetic, aliquots, zero volume, unit conversions, blood-volume methods, RCH's published child example, all 18 NBA neonatal table entries with their historical product concentration, input errors, and exclusions. Details and browser checks are recorded in [VALIDATION.md](VALIDATION.md).

Passing software checks does not quantify clinical accuracy or justify treatment decisions. Actual product concentration, blood volume, retention and post-transfusion equilibration vary. No patient-specific uncertainty interval is provided.
